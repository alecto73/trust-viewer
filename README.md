# 부동산 신탁사 재무건전성 지표

금융감독원 금융통계정보시스템(FISIS) 오픈API에서 부동산신탁사 14개사의 최근 12개 분기
재무건전성 지표를 받아, PC와 모바일에서 같은 화면으로 조회하는 정적 웹 앱입니다.

빌드 도구, 데이터베이스, 상시 구동 서버가 없습니다. Python 표준 라이브러리만 쓰는 수집
스크립트 하나와 HTML 파일 하나가 전부입니다.

```
GitHub Actions (매주 월요일 05:00 KST 확인 / 수동 실행)
      │  python scripts/update_data.py
      ▼
FISIS 오픈API  ──▶  data/fisis_data.json  ──▶  scripts/embed_seed.py ──▶ index.html
      │                                                                      │
      └────────────────── git commit & push ─────────────────────────────────┘
                                    │
                                    ▼
                        Netlify 자동 빌드 → CDN 배포
```

## 1. FISIS 오픈API 실제 규격

이 프로젝트에서 가장 중요한 부분입니다. 아래는 `fisis.fss.or.kr/page/api-spec.jsp`를
확인하고 실제 호출로 검증한 내용입니다.

### 엔드포인트

| 용도 | 서비스 |
| --- | --- |
| 통계 수치 조회 | `statisticsInfoSearch.json` |
| 금융회사 코드 조회 | `companySearch.json` |
| 통계표 목록 조회 | `statisticsListSearch.json` |
| 계정항목 코드 조회 | `accountListSearch.json` |

기본 주소는 `https://fisis.fss.or.kr/openapi/` 입니다.

### 검증 과정에서 걸렸던 함정

- **`financialInfoSearch` 라는 서비스는 없습니다.** 통계 수치는 `statisticsInfoSearch` 입니다.
- **`openfisis.fss.or.kr` 도메인은 존재하지 않습니다.** 호스트는 `fisis.fss.or.kr` 하나입니다.
- `http://` 로 호출하면 **307 리다이렉트**가 떨어집니다. `https://` 를 직접 쓰십시오.
- 기본 User-Agent로 호출하면 **503**이 반환됩니다. 브라우저 User-Agent 헤더가 필요합니다.
- 기간 파라미터는 `startBaseYm`/`endBaseYm`이 아니라 **`startBaseMm`/`endBaseMm`** 입니다.
- 조회 기간은 **40분기를 초과할 수 없습니다**(`err_cd` 103).
- 금액은 `baseAmt`가 아니라 **`a`, `b`, `c`, `d` 컬럼**에 담겨 옵니다. 각 컬럼의 의미는
  같은 응답의 `description` 에 들어 있습니다. 예를 들어 요약재무상태표는 `a`=금액,
  `b`=구성비이고, 자산건전성 분류표는 `a`~`e`가 정상·요주의·고정·회수의문·추정손실입니다.
- `err_cd`가 `000`이 아니면 데이터가 비어 있어도 HTTP 200이 옵니다. 반드시 확인해야 합니다.
- 인증키를 URL 쿼리에 그대로 실어 보내는 방식입니다. 비영리 키는 일일 호출 한도가
  있고(`err_cd` 020), 영리 키는 신청 IP에서만 동작합니다(`err_cd` 021).

### 부동산신탁 권역 코드

회사 목록은 `companySearch.json?partDiv=M` 으로 받습니다. 통계표 목록은
`statisticsListSearch.json?lrgDiv=M&smlDiv=A|B|E` 입니다(A 일반현황, B 재무현황,
E 주요경영지표). 신탁계정 쪽 통계는 별도 권역인 공통(신탁) `lrgDiv=B` 아래
`smlDiv=E`(부동산신탁), `smlDiv=F`(신탁보수)에 있습니다.

회사코드는 하드코딩하지 않고 매 실행 시 API로 받아옵니다. 회사명에 `[폐]`가 붙은
폐업사(코레트신탁, 한국부동산신탁, 구 코람코자산신탁)는 제외해 14개사가 남습니다.

### 사용 중인 통계표

| 통계표 | 이름 | 뽑는 항목 |
| --- | --- | --- |
| `SM005` | 요약재무상태표(고유계정) | `A` 자산총계, `A45` 신탁계정대, `A472` 신탁계정대 대손충당금, `A44` 대지급금, `B` 부채총계, `B2` 차입부채, `C` 자본총계, `C1` 자본금, `A1` 현금및예치금 |
| `SM007` | 요약손익계산서(고유계정) | `A` 영업수익, `A11` 신탁보수, `C` 영업이익, `G` 당기순이익 |
| `SM009` | 자본적정성(영업용순자본비율) | `A` 영업용순자본, `B` 총위험액, `C` NCR |
| `SM013` | 자산건전성(고정이하자산비율) | `A` 고정이하자산, `B` 분류대상자산, `C` 비율 |
| `SM016` | 자산건전성 분류 | 계정 `K`(신탁계정대)의 등급별 분포 |

지표를 더 넣고 싶으면 `scripts/discover.py` 로 코드를 찾아 `update_data.py` 의
`MAP_*` 딕셔너리에 한 줄 추가하면 됩니다.

```bash
python scripts/discover.py tables
python scripts/discover.py accounts SM005 신탁계정대
python scripts/discover.py peek 0010902 SM016 202603
```

## 2. 손익 항목은 누적이 아니라 분기 단독입니다

설계에서 가장 크게 바로잡은 지점입니다.

FISIS 요약손익계산서의 분기 수치는 **해당 분기에 발생한 금액**입니다. 누적이 아닙니다.
무궁화신탁 당기순이익을 보면 2025Q1 −60억, Q2 −447억, Q3 −146억, Q4 −384억으로,
누적이라면 나올 수 없는 흐름입니다.

따라서 `당기순이익 × (4 / 분기번호)` 같은 연환산은 틀린 계산입니다. 이 프로젝트는
**최근 4개 분기 합계(TTM)** 로 순이익·영업수익을 집계하고 그것으로 ROA·ROE를 계산합니다
(`roa_ttm`, `roe_ttm`). 화면에도 "4분기 롤링"으로 표기합니다.

TTM 계산에 앞선 3개 분기가 필요하므로, 수집은 표시 구간(12분기)보다 넉넉하게 받아
잘라냅니다.

## 4. 분기 자동 갱신

화면은 항상 **조회 시점 기준 최근 12개 분기**를 보여줍니다. 이를 무인으로 유지하기 위한
장치가 네 개 있습니다.

**롤링 조회 창.** 시작월을 고정하지 않고 실행 시점의 분기말부터 거꾸로 17분기
(표시 12 + TTM용 3 + 공시 지연 여유 2)를 계산해 요청합니다. 시간이 지나도 창이 함께
밀리므로 손댈 일이 없고, FISIS의 40분기 제한에도 걸리지 않습니다. 특정 구간을 강제하려면
`FISIS_START_MM` / `FISIS_END_MM` 환경변수로 덮어쓸 수 있습니다.

**매주 확인, 변경 시에만 커밋.** 분기 업무보고서가 FISIS에 실리는 시점은 분기마다
차이가 있어 "분기 1회 실행"은 한 번 놓치면 3개월을 기다려야 합니다. 그래서 워크플로는
매주 월요일 05:00(KST, cron `0 20 * * 0` = UTC 일요일 20:00)에 확인만 합니다.
`update_data.py` 는 수집 시각(`generated_at`)을 뺀 내용이 기존 파일과 같으면 파일을 다시 쓰지 않고,
워크플로는 `git diff --staged --quiet` 로 실제 변경이 있을 때만 커밋합니다. 변경이 없으면 Netlify 재배포도 일어나지 않습니다.

**미완성 분기 제외.** 새 분기가 열릴 때 일부 회사만 먼저 올라오는 구간이 생깁니다.
자산총계가 채워진 회사가 과반이 안 되는 분기는 아직 미완성으로 보고 표시 대상에서
빼고, 로그에 `분기 2026Q2 제외: 3/14개사만 수집됨` 형태로 남깁니다.

**후퇴 방지 가드.** 인증키 만료, 일일 한도 초과, FISIS 점검 등으로 빈 응답이 오면
정상 데이터가 0으로 덮여 쓰이는 사고가 납니다. `guard()` 가 커밋 전에 세 가지를 확인해
하나라도 어긋나면 종료코드 1로 실패시키고 **기존 파일을 그대로 남깁니다**.

- 최신 분기 수집률이 과반 미달인 경우
- 새로 받은 최신 분기가 기존 파일보다 과거인 경우
- 분기 수가 기존보다 줄어든 경우

실패하면 Actions에 빨간 표시가 남으므로 원인을 확인한 뒤 `Run workflow` 로 다시 돌리면
됩니다. 화면 맨 아래에도 최신 분기와 다음 갱신 대상 분기가 표시됩니다.

## 3. 지표 정의

금액은 억원, 비율은 %입니다. 모두 **고유계정 기준**이며 신탁계정과 분리됩니다.

| 지표 | 산식 | 비고 |
| --- | --- | --- |
| NCR | FISIS 공시값 직접 수집 | 규제 기준선 150% |
| 신탁계정대/자기자본 | 신탁계정대 ÷ 자본총계 | 대지급 투입 강도 |
| 신탁계정대 충당금 적립률 | 신탁계정대 대손충당금 ÷ 신탁계정대 | 손실 인식 정도 |
| 신탁계정대 고정이하비율 | (고정+회수의문+추정손실) ÷ 분류 합계 | `SM016` 계정 K |
| 고정이하자산비율 | FISIS 공시값 | 분류대상 자산 전체 기준 |
| 부채비율 | 부채총계 ÷ 자본총계 | |
| 순차입금의존도 | (차입부채 − 현금및예치금) ÷ 자산총계 | 음수는 순현금 |
| ROA / ROE | 4분기 순이익 합계 ÷ 기말 총자산 / 자본총계 | |
| 신탁보수/영업수익 | 신탁보수 ÷ 영업수익 | 본업 의존도 |

평균 계산에 쓰이는 분자·분모 원천값(`total_liabilities`, `net_borrowings`,
`net_operating_capital`, `total_risk`, `tal_classified_total` 등)도 함께 저장합니다.

### NCR을 읽을 때의 주의

NCR의 분모는 위험가중자산이 아니라 총위험액이라, 회사 규모에 따라 값의 자릿수가 크게
달라집니다. 2026Q1 기준 우리자산신탁 4,358%와 한국토지신탁 205%의 차이를 안전성 차이로
직접 해석하면 안 됩니다. 규제선 150% 대비 여유와 **추세 방향**으로 보는 편이 맞습니다.
화면에서 스파크라인을 지표 값 옆에 항상 붙여둔 이유가 이것입니다.

화면의 양호·주의·경계 구간은 NCR 150%를 제외하면 규제 기준이 아니라 이 앱에서 정한
참고 기준입니다. 기준을 바꾸려면 `index.html` 상단 `METRICS` 배열의 `band` 값을 고치면
됩니다.

## 5. 화면 구성

PC용 표와 모바일용 카드를 따로 만드는 대신, **세로형 위험 서열 래더** 하나로 양쪽을
처리합니다. 14개사 × 1개 지표는 세로로 쌓으면 모바일에서 그대로 읽히고, 넓은 화면에서는
같은 행에 스파크라인과 전분기 대비 증감이 붙습니다.

- **업계 요약 카드** — 첫 화면 상단에 영업용순자본비율, 부채비율, 신탁계정대 잔액,
  신탁계정대 고정이하비율, 신탁계정대 충당금, 당기순이익(분기) 6개 카드를 둡니다. 비율 카드는
  합산 비율과 분자·분모 합계 금액을, 금액 카드는 전 신탁사 합계와 산술평균을 보여주며,
  전분기 대비 증감을 함께 표시합니다. 카드를 누르면 해당 지표의 래더로 이동합니다.
- **위험 서열 래더** — 선택한 지표로 14개사를 정렬. 막대 색이 등급, 축 위의 실선이
  기준선(NCR 150%, 손익 지표는 0), **점선이 업계 평균**입니다. 음수가 나오는 지표는 0을
  기준으로 좌우로 갈라지고, 축 범위를 넘는 값은 사선 해칭으로 표시합니다. 비율 지표는
  회사별로 구성 금액(예: NCR은 영업용순자본·총위험액, 충당금 적립률은 충당금 적립액·신탁계정대)을
  함께 보여주고, 래더 상단에 업계 합산 비율과 구성 금액 합계를 표시합니다.
- **업계 평균** — 비율 지표는 회사별 비율을 다시 평균하지 않고 14개사 분자 합계를 분모
  합계로 나눈 **합산 기준**으로 계산합니다. 규모 차이가 큰 업권이라 단순 평균은 소형사
  극단값에 끌려가기 때문입니다(예: 신탁계정대/자기자본은 단순 평균 271%, 합산 171%).
  금액 지표는 전 신탁사 합계와 산술평균을 함께 표시합니다. 매트릭스 표 맨 아래
  행에도 같은 값이 들어갑니다.
- **행 펼침** — 회사명을 누르면 그 회사의 핵심 8개 지표 12개 분기 추이가 인라인으로 열립니다.
- **전체 지표 매트릭스** — 14개사 × 13개 지표(당기순이익 추가). 머리글을 눌러 정렬, CSV로 내려받기.

차트 라이브러리를 쓰지 않고 스파크라인을 SVG로 직접 그립니다. 외부 의존성은 Pretendard
웹폰트 하나뿐이고, 폰트 로딩이 실패해도 시스템 한글 폰트로 떨어집니다.

## 6. 실행

### 로컬에서 데이터 갱신

```bash
# Windows PowerShell
$env:FISIS_API_KEY = "발급받은_인증키"
python scripts/update_data.py
python scripts/embed_seed.py

# macOS / Linux
export FISIS_API_KEY="발급받은_인증키"
python3 scripts/update_data.py
python3 scripts/embed_seed.py
```

14개사 × 5개 통계표라 70여 회 호출이 발생하고 2~3분 걸립니다.
`pip install` 은 필요 없습니다. 표준 라이브러리만 씁니다.

### 화면 확인

`index.html` 을 그냥 더블클릭해도 내장 스냅숏으로 정상 동작합니다. 화면 맨 아래에
지금 보고 있는 데이터의 출처(내장 스냅숏 / `data/fisis_data.json`)와 수집 시각이
표시되니 헷갈릴 일은 없습니다.

로컬 서버로 최신 JSON까지 확인하려면:

```bash
python -m http.server 8000   # → http://localhost:8000
```

### 배포

1. GitHub에 비공개 저장소를 만들고 푸시합니다.
2. 저장소 `Settings → Secrets and variables → Actions` 에 `FISIS_API_KEY` 를 등록합니다.
3. Netlify에서 `Add new site → Import an existing project` 로 저장소를 연결합니다.
   빌드 명령은 비워두고 publish 디렉터리는 `.` 입니다(`netlify.toml`에 이미 있습니다).
4. `Actions` 탭에서 `FISIS 분기 데이터 갱신` 을 한 번 수동 실행해 동작을 확인합니다.

이후에는 분기마다 워크플로가 자동으로 돌고, 커밋이 올라가면 Netlify가 감지해 재배포합니다.

---

## 7. 인증키 관리

인증키를 소스에 직접 적지 마십시오. `update_data.py` 는 `FISIS_API_KEY` 환경변수만
읽습니다. 하드코딩해서 커밋하면 저장소를 비공개로 두더라도 협업자·CI 로그·클론 이력에
그대로 남습니다.

이미 어딘가에 키를 평문으로 붙여넣거나 커밋한 적이 있다면, FISIS에서 재발급받아
교체하는 편이 안전합니다.

## 8. 다음에 붙일 만한 것

- **신탁계정 통계 연동** — `lrgDiv=B, smlDiv=E` 의 수탁고·신탁보수 통계표를 붙이면
  고유계정만으로는 안 보이는 사업 포트폴리오(차입형 / 책준형 / 관리형) 구성을 볼 수 있습니다.
- **분기 변화 알림** — 새 분기 수집 시 NCR이 기준선에 근접하거나 등급이 내려간 회사를
  워크플로가 요약해 Actions 로그나 Slack에 남기는 방식.
- **2사 비교 화면** — 특정 두 회사의 12개 분기 지표를 겹쳐 보는 뷰.
- **DART 교차검증** — 재무제표 항목은 DART 별도재무제표와 대조해 이상치를 잡을 수 있습니다.

## 파일 구조

```
.
├── .github/workflows/fisis_sync.yml   매주 월요일 확인, 변경 시에만 커밋
├── scripts/
│   ├── update_data.py                 FISIS 수집 + 지표 계산 + 후퇴 방지 가드
│   ├── embed_seed.py                  JSON을 index.html 에 내장
│   └── discover.py                    회사·통계표·계정 코드 탐색기
├── data/fisis_data.json               수집 결과 (14개사 × 12분기)
├── index.html                         대시보드 (단일 파일)
└── netlify.toml                       배포 설정
```

데이터 출처는 금융감독원 금융통계정보시스템(FISIS)입니다. FISIS 수록 통계는 국가승인통계가
아니며 금융회사가 작성한 업무보고서를 기초로 합니다.
